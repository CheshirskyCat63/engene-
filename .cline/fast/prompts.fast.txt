FAST PROMPTS

[local-fix]
Stay in Act mode.
Use .cline/fast first.
Inspect only the owning module and directly related files.
Do not read broad canon unless ownership or contracts are affected.
Make the smallest safe fix.
Run narrow validation first.
Report changed files, commands, result, and remaining risk.

[compile-fix]
Stay in Act mode.
Use @problems and @terminal if available.
Inspect the error site and its direct module boundary.
Fix only what is required to make the owning crate green.
Run cargo check -p <crate> first.
Do not widen scope unless the error proves wider impact.

[test-fix]
Stay in Act mode.
Use .cline/fast and direct test files first.
Inspect failing test and the nearest owning implementation.
Make minimal edits.
Run the narrowest failing test first, then crate-scoped validation if needed.

[runtime-trace]
Trace ownership first.
Use runtimeMap.md, pathIndex.md, and .cline/fast/runtime.fast.md.
Inspect apps/, crates/, and game/ only where directly relevant.
Do not collapse engine/sdk/game roles.
Summarize actual ownership and touched paths.

[canon-check]
Inspect .cline/fast/canon.fast.md and .cline/memory-bank/canonIndex.md first.
Open only the canonical files directly relevant to the boundary or contract in question.
Report code/canon agreement or mismatch clearly.
Do not rewrite canon unless required.

[refactor-small]
Stay in Act mode.
Keep the refactor local, explicit, and reversible.
Inspect direct callers and direct dependencies only.
Do not broaden architecture.
Run focused validation.
Report exact scope.

[run-build]
Inspect ROOT_DOCS_INDEX.txt, commands.fast.txt, and root helper files first.
Use run_game.ps1, run_sdk.ps1, Justfile, and root scripts only as needed.
Prefer the smallest command that proves the path works.

[memory-refresh]
Update memory-bank only for durable changes:
- ownership
- runtime map
- decision
- progress milestone
Keep entries dense and short.
Do not mirror full docs or code.

[canon-sync]
If canonical docs changed:
- refresh canonIndex.md
- refresh canon.fast.md
- refresh path/runtime fast files only if ownership or paths changed
Do not rewrite unrelated compact files.

[new-task-handoff]
Before starting a fresh task:
- update memory bank
- summarize current progress briefly
- carry only compact context into the new task
Prefer /newtask after milestone completion.

[compact-now]
Use /smol when context is getting crowded but work should stay in the same task.
