# System Patterns

core patterns:
- path-first reasoning
- owning crate/module first
- narrow search first
- local proof before broad theory
- focused cargo check/test first
- canon only for architecture/contracts/ownership/runtime law

editing patterns:
- prefer local reversible edits
- avoid broad rewrites
- avoid convenience coupling
- avoid dependency growth without proof

safety patterns:
- no auto push
- no legacy/quarantine edits unless requested
- report scope and risk explicitly
