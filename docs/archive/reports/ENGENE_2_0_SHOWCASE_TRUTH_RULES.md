# ENGENE 2.0 Showcase Truth Rules

## Purpose
Ensure showcase proves real runtime capability rather than demo-only theater.

## Forbidden in showcase validation
1. Dev-only cheats to force desired outcomes.
2. Special-case code branches active only for demo scene.
3. Pre-scripted fake outcomes bypassing runtime simulation systems.
4. Non-runtime visual tricks presented as simulation results.

## Allowed scripting (explicitly permitted)
- Authored scenario scripting.
- Deterministic trigger schedules.
- Content-driven wave launches.
- Authored weather onset timelines.
- Replay-controlled camera/debug sequences.

Allowed scripting is valid only if it does not:
- Bypass runtime state transitions.
- Invent impossible outcomes.
- Skip system contracts.
- Replace causal chains with canned results.

## Required proof conditions
- All showcased outcomes are produced through shipping runtime pathways.
- Same scenario can be rerun with equivalent rules and bounded variance.
- SDK debug overlays can trace cause/effect chains for each flagship event.
- Save/load mid-scenario preserves systemic state continuity.

## Verification checklist
- Ballistic penetration trace confirms per-layer energy usage.
- Destruction events link to structural/support state transitions.
- Fire spread links to burnability + wind + wetness states.
- Leak/wetness behavior linked to puncture/container state.
- Audio occlusion linked to geometry/material path.
- AI hearing reactions linked to runtime audio events.

## Evidence requirements
- Runtime logs with event IDs.
- Metrics snapshot before and after each flagship trigger.
- Optional replay artifact hash for reproducibility.
